Phase 7b-a: Core Dark Matter

Add dark_matter to game-service PlayerData, no cross-service calls

Backend Architecture (refined)

Game-service: Add dark_matter to Planet or new entity

  • Add int darkMatter field to PlayerData (or create PlayerResource entity in game-service)
  • Simpler: use existing Planet.playerId — but DM is per-player, not per-planet
  • New entity: PlayerResource (player_id, dark_matter) — one row per player

Game-service: DarkMatterService

  • getDarkMatter(Long playerId)
  • addDarkMatter(Long playerId, int amount)
  • spendDarkMatter(Long playerId, int amount) → boolean

Speed-Up Cost Formula

  • Calculate remaining seconds on queue item
  • Cost = ceil(remainingSeconds / (60 * 30)) — 1 DM per 30 minutes of remaining time
  • Minimum 1 DM per speed-up

API Endpoints (game-service)

  • GET /planets/{id}/dark-matter — returns current DM balance
  • POST /planets/{id}/buildings/{pos}/speed-up — spend DM to complete construction
  • POST /planets/{id}/shipyard/{queueId}/speed-up — spend DM to complete ship/defense build
  • POST /technologies/speed-up — spend DM to complete research

Migration V9

New table: player_resource

CREATE TABLE player_resource (
    id BIGSERIAL PRIMARY KEY,
    player_id BIGINT NOT NULL UNIQUE,
    dark_matter INT NOT NULL DEFAULT 0,
    FOREIGN KEY (player_id) REFERENCES player(id)
);
