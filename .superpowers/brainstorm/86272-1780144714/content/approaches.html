Phase 7 — Resources/Economy: Approaches

You picked all 8 features. How should we batch them?

A

Big Bang — Everything in One Phase

EconomyService, storage caps, production ticks, fusion reactor, energy deficit, dark matter, header bar, rate display — one design doc, one plan, one implementation cycle.

Pros

  • Single consistent pass through the codebase
  • One migration (V9)
  • Coherent end-to-end

Cons

  • Large scope — estimation risk
  • Dark matter feature creep
  • Long implementation cycle
B

Core Economy First → UI + Dark Matter Later

Phase 7a: EconomyService, storage caps, production tick, fusion reactor, energy deficit
Phase 7b: Resource header bar, production rate display
Phase 7c: Dark matter earning + spending

Pros

  • 7a delivers meaningful gameplay value fast
  • Smaller batches = faster iteration
  • Dark matter gets its own design

Cons

  • Three design cycles
  • UI changes may touch 7a backend
  • Slightly more overhead
C

Refactor-First → Core → UI → Dark Matter

Phase 7a: EconomyService refactor + storage caps (no new behavior)
Phase 7b: Production tick + fusion reactor + energy deficit
Phase 7c: Resource header bar + rate display
Phase 7d: Dark matter

Pros

  • Clean foundation before adding features
  • Each phase is small and focused

Cons

  • 7a is pure refactor — no visible value
  • 4 design cycles is a lot of overhead
  • Higher risk of interface thrash

Click an option to select. I recommend B (Core → UI → Dark Matter) — the core economy ships fastest, UI is a natural follow-up, and dark matter deserves its own design treatment.
